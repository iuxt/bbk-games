# 伏魔记道具数据逆向：装备武器与投掷暗器

本文档记录从 fmj 引擎 `.lib` 资源中逆向提取「装备武器（刀剑）」与「投掷暗器」数据的过程与结果，
供后续核对、平衡性分析或引擎改动时参考。

> 数据来源：`rpg/roms/fmj_zsb.lib`（**伏魔记正式版**），共 32 把装备武器 + 30 种投掷暗器。
> 字段含义与偏移全部对照 `rpg/core.js`（已编译的 fmj 引擎）核实。

---

## 一、排查过程（方法论）

### 1. 道具在 `.lib` 中如何组织

`.lib` 是 fmj 引擎的资源库（magic `LIB`），布局（与 `scripts/gam2lib.mjs` 的提取算法、`core.js` 的 `DatLib.getAllResOffset_0` 完全一致）：

- 头部 `0x10` 字节。
- **索引表 @ `0x10`**：每条 3 字节 `(resType, type, index)`，遇到 `resType == 0xFF` 结束。
- **偏移表 @ `0x2000`**：每条 3 字节 `(block, low, high)`，数据偏移 `= block*0x4000 + (high<<8 | low)`。
- 索引表第 `k` 条对应偏移表第 `k` 条，定位到该资源在文件中的起始字节。

`resType` 取值（`DatLib$ResType`，`core.js:48310` 起）：`GUT=1 / MAP=2 / ARS=3 / MRS=4 / SRS=5 / GRS=6 / TIL=7 / ACP=8 / GDP=9 / GGJ=10 / PIC=11 / MLR=12`。
**道具资源 = GRS = 6。** 道具按 `type` 分类（`DatLib.getGoods_0`，`core.js:48227`）：

| type | 类别 | type | 类别 |
|---|---|---|---|
| 1–5 | GoodsEquipment（装备：武器/防具/饰等） | 6 | GoodsDecorations（饰品） |
| **7** | **GoodsWeapon（装备武器：刀剑）** | **8** | **GoodsHiddenWeapon（投掷暗器）** |
| 9/10/11 | GoodsMedicine 系列（药品） | 12 | GoodsStimulant |
| 13 | GoodsTudun（土遁/卷轴） | 14 | GoodsDrama（剧情道具） |

→ 要拿「刀剑」就筛 `resType==6 && type==7`；「投掷暗器」筛 `type==8`。

### 2. 一条道具记录的字段偏移

公共部分由 `BaseGoods.setData_ir89t6$`（`core.js:47080`）解析：

| +4 | sumRound | 1 字节 |

### 3. 关键坑：字节符号（单字节属性增量是「原码」而非补码）

`mBuffer_0`（装载 `.lib` 的缓冲区）类型决定符号。追溯链：
`File.readAll → hexDecode → toByteArray → new Int8Array`（`core.js:54147` / `6900`）。
**Kotlin `ByteArray` 编译为 JS `Int8Array`（补码 -128..127）**。但伏魔记单字节属性增量
（mMpMax/mHpMax/mdf/mlingli/mSpeed/mLuck）在 `.lib` 里以 **原码（sign-magnitude）** 存放：
**bit7 为符号位，bit0..6 为数值**。因此：

- `get1ByteSInt(buf, start)` 已按原码解码：`b=buf[start]&255; (b&0x80)?-(b&0x7f):b`。
  例如 金缕衣「身法-10」字节 `0x8a` → bit7 置位、数值 `0x0a=10` → `-10`。
- ⚠️ 若直接返回 `buf[start]`（Int8Array 补码），`0x8a` 会被读成 `-118`，于是 99 身法装备后变
  `99+(-118)=-19`。这正是曾出现的 bug（与 `costMp` 同源，见 `tests/test_rpg_equip_stat_sign.test.mjs`）。
- `mat = buf[offset+25] & 255` —— 显式转**无符号**，故攻击力恒为 0..255。
- 负值 = 诅咒/特殊装备的属性惩罚（例：嗜血剑攻 250 但血/防/灵/运大降）。

> 验证：所有带惩罚字节的装备，其游戏内描述文本都与原码解读**逐一吻合**（嗜血剑
> `0xa8/0x9e/0x9e/0xb2` = 灵力-40/防御-30/吉运-30/血上限-50；补码则会读成 -88/-98/-98/-78，与描述矛盾）。

### 4. 验证（原始字节逐字段对照）

抓取 `+22..+29` 原始字节核对，布局与符号解读全部成立：

| 武器 | 原始字节[+22..+29] | 解读 |
|---|---|---|
| 木剑 | `00 00 00 02 00 00 00 00` | mat=2，其余全 0 → **布局证实** |
| 嗜血剑 | `00 b2 9e fa a8 00 00 9e` | mat=250(0xfa)、血-50(0xb2)、防-30(0x9e)、灵-40(0xa8)、运-30(0x9e) → 诅咒剑，**原码解读与描述完全吻合** |
| 砍刀 | `00 00 00 0a 00 82 00 00` | mat=10、速度 0x82 = **-2**（原码：bit7 置位，数值 2） |

> 说明：早期文档曾把 `0x82/0x8a/0xa8` 这类字节按 Int8Array 补码读成 -126/-118/-88 等「大负值」，
> 误判为原数据笔误。实为单字节属性增量采用**原码**存放（见上节），正确解读为 -2/-10/-40 等小幅惩罚，
> 与装备描述一致。

## 二、装备武器 GoodsWeapon（type=7）—— 共 32 把

**装备位**（`mEnable` 掩码）：`剑(1)`=角色1 主角剑系；`刀(4)`=角色4 刀/匕系；`双(2)`=角色2 双剑/双刀系。
**攻击** = `mat`，装备时 `player.attack += mat`。
**投掷伤害** = `mat × 50`（`GoodsWeapon.affectHp` 计算属性，`core.js:47641`）——武器投掷只造成该值的生命伤害（不减真气、不附状态：`Throwable.attack` 中武器的 `affectMp`/`buff` 均未赋值）。

## 四、两类武器的关系

装备武器 `GoodsWeapon` 同时实现 `Throwable` 接口（`core.js:47663`），并复用 `Throwable.attack`（`core.js:47120`）：

```js
Throwable.prototype.attack = function(other) {
  other.hp  = other.hp  - this.affectHp  | 0;   // 武器: affectHp = mat * 50
  other.mp  = other.mp  - this.affectMp  | 0;
  other.beAttackedWithBuff(this.buff, 0);
};
```

即**装备武器也能被投掷**，投掷伤害 = `affectHp` = **`mat × 50`**（`GoodsWeapon.affectHp` getter，`core.js:47641`）。
例如嗜血剑 mat=250 → 投掷伤害 12500；木剑 mat=2 → 投掷伤害 100。投掷动作 `ActionThrowItemOne`（`core.js:44086`）会调用 `weapon.attack(target)` 并按真实 HP 差值显示伤害数字（投掷功能已完整实现，非桩函数）。

## 附：复现脚本

下列 Node 脚本可从任意 fmj 系 `.lib` 提取武器（type=7）或暗器（type=8）数据，字段偏移与上文一致：

```bash
# 用法：node extract.mjs <xxx.lib> <7|8>
node extract.mjs rpg/roms/fmj_zsb.lib 7    # 装备武器
node extract.mjs rpg/roms/fmj_zsb.lib 8    # 投掷暗器
```

```js
// extract.mjs —— 从 fmj .lib 提取 GRS 道具记录（type=7 武器 / type=8 暗器）
import { readFileSync } from "node:fs";
const dec = new TextDecoder("gbk");
const u = new Uint8Array(readFileSync(process.argv[2]));
const wantType = Number(process.argv[3] || 7);
// 索引表 @0x10 / 偏移表 @0x2000
const e = []; let i = 0x10, j = 0x2000;
while (u[i] !== 0xff) {
  e.push({ rt: u[i], t: u[i+1], ix: u[i+2], o: u[j]*0x4000 + ((u[j+2]<<8)|u[j+1]) });
  i += 3; j += 3;
}
const u16 = o => (u[o]&255) | ((u[o+1]&255)<<8);
const s16 = o => { const v=u16(o); return v>=0x8000 ? v-0x10000 : v; };
const s8  = o => { const v=u[o]&255; return v>=0x80 ? v-0x100 : v; };
const str = o => { let x=o; while (u[x]) x++; return dec.decode(u.subarray(o,x)); };
for (const r of e.filter(x => x.rt===6 && x.t===wantType).sort((a,b)=>a.ix-b.ix)) {
  const o = r.o;
  if (wantType === 7) {
    console.log([r.ix, str(o+6), u16(o+18), u16(o+20), u[o+25]&255,
      s8(o+22), s8(o+23), s8(o+24), s8(o+26), s8(o+27), s8(o+29), u[o+28]&255, u[o+3]&255].join(" | "));
    // 序号|名称|买价|售价|攻击|气上限|血上限|防御|灵力|速度|幸运|状态位|装备位
  } else {
    console.log([r.ix, str(o+6), u16(o+18), u16(o+20), s16(o+22), s16(o+24), u[o+28]&255].join(" | "));
    // 序号|名称|买价|售价|生命伤害|真气伤害|状态位
  }
}
```
